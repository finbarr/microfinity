# Party contract (engine and client coordination)

Integration update: the user has assigned removal of replay UI, APIs and recording to Worker01. This handoff preserves the already-tested compatibility behavior described below; replay support is not a requirement for the resulting product and no further replay work is assigned to Worker03.

## Client and API

- Preserve `POST /api/rooms` and the WebSocket upgrade at `/socket`. Existing authenticated requests with either `{versions: string[], settings: ...}` or `{random: RandomFilters, settings: ...}` remain valid. The response keeps `{id, selection}`. Settings are now optional; default target is one participant, mode is automatic (`native` is the legacy request name), and the engine fills opponents as needed. Explicit old target/bot/variant settings are still accepted.
- Add an authenticated way to create a **shareable empty lobby**: `POST /api/rooms` with `{lobby: true}` (or no selection). Return `{id, selection: null}`. The host joins that room through the existing socket join frame `{type:"join", roomId, token}`. Empty lobbies are valid only before start; a start with no selected cartridges is rejected.
- Keep `joined` as `{type:"joined", roomId, playerId}`. Keep `state` as the authoritative snapshot, including `phase`, `hostId`, `revision`, `playlist`, `seats`, `playerId`, `manifest`, `view`, `results`, and error/timing fields. Empty lobby state has `phase:"lobby"`, `playlist:[]`, and no active manifest/view. `seats` reports human/AI ownership and connected status; clients must render it and use the host id for permissions.
- Host selection uses existing `{type:"playlist", revision, versions:[versionId,...]}` with revision checking; an empty array clears the queue. Host-only random selection is `{type:"random", revision, filters?: RandomFilters}`. Omitted filters mean four random finished cartridges; `count` (1–12) and `seed` are optional, and old filters remain accepted. It resolves and publishes the same pinned playlist shape as manual selection. A selection change broadcasts a new revision. Both paths apply identical eligibility/adaptation rules.
- `{type:"start", newSeed?: boolean}` remains host-only. To choose and start atomically in the lobby, also accept `{type:"start", revision, versions:[...]}` or `{type:"start", revision, random:{count?:4,seed?:number}}`. Joiners can connect, wait, and play when started; they cannot mutate queue/random filters or start. Existing `ready` remains accepted for compatibility, but it is not a start gate. Preserve `loaded`, `input`, `release`, and `clock-reply` frames.

## Seats and lifecycle

- A lobby has 1–4 human capacity. The creator occupies the host seat when connected. A join assigns the same guest back to its prior seat on reconnect; a new join takes a free human seat. A fifth distinct human receives a clear full-room error. On host disconnect, the connected host successor is authoritative; reconnecting guest identity and seat are preserved where possible.
- Queue edits and start are accepted only from the current host and only in the lobby. Reject stale revisions and changes after start. Joiners never control games or AI seats from setup UI.
- Engine owns player slots and any AI seats. The lobby grows as guests join, up to four seats; it reserves the creator even if an invitee connects first. At start it fills any required legacy minimum with AI seats, preserving explicit older target counts. Slots are stable `p0`…`p3` throughout a match. Do not expose internal `native`, `race`, `obstruction`, `pressure`, or `party-v1` adapter choices in normal UI.
- A full room rejects additional joins. Reconnecting the same guest resumes its seat and current round subject to existing epoch/input ownership checks. A disconnected human seat falls back to the engine controller until that guest resumes; it does not become a second human.

## Cartridge and generation contract

- All new cartridges are playable for 1–4 human participants. Generation is prompt-driven: no author/user choice for min/max players or clock. The model selects realtime vs action clock from the prompt. **Worker01: omit `meta.players` and `meta.modifiers` in new `defineGame` sources** (SDK defaults are `[1,4]` and `[]`). For `participation:'individual'`, author a single attempt against `ctx.players[0]`; the engine runs a separate equal-seed attempt for every participant. For `simultaneous` or `rotating`, author the shared rules against the actual `ctx.players` array for any length 1–4. Keep `role` and bounded timeout behavior correct for that array. Explicit old metadata remains accepted when remixing old sources.
- Keep reading saved versions' historical `players`, `clock`, participation/world, and modifier metadata as compatibility input. Do not claim broader native participation by changing metadata alone; runtime behavior, observation isolation, score/outcome mapping, turn/input ownership, bounded finish and replay data must agree.
- Existing valid saved-version room requests and challenge definitions remain playable; any restored pinned playlist uses its resolved versions and settings. Random and manual selections use the same engine compatibility decision.
- New ordinary rounds record `mode:'party-v1'`. `Sandbox` implements this adapter outside the pinned runtime using its original native init/step/observe/save/restore API. Native shared rules run together whenever the roster fits; legacy games whose maximum is smaller use private equal-seed worlds, with deterministic practice opponents if their native minimum exceeds one. Each world uses local contiguous IDs; observations retain their opaque game data and expose `gamePlayerId` for engine controllers, while public score/role/HUD IDs identify party seats. Browser replays use the same Sandbox adapter automatically, so **no replay component changes or saved-version rewrites are needed**. Old recorded modes continue using their original pinned runtime behavior.
- Private action worlds advance only on their own input, opponent decision, or deadline. The adapter reports the next engine wake time and keeps per-world elapsed time/turn deadlines in its snapshot; another guest’s inputs cannot advance or postpone an idle attempt. Those internal wake times require no client messages.
- Compilation preflight now executes all four party sizes. Its independent watchdog is 60 seconds; the existing generation work deadline/cancellation can stop it sooner. The generation integration test's polling allowance is 70 seconds to cover that validation work.
